# Оптимізація швидкості завантаження: квіз /onboarding та сторінка оплати

**Дата:** 2026-08-18
**Статус:** затверджено користувачем

## Мета

Зменшити час завантаження всіх сторінок опитувальника (`/onboarding/[step]`) і сторінки
оплати (`/payment/plan`), не змінюючи поведінку воронки, платіжного флоу та аналітики.

Базові вузькі місця (за аудитом 2026-08-18):

- `posthog-js` (~60 КБ gzip) статично імпортується фасадом `src/lib/analytics/index.ts`
  і потрапляє в First Load JS кожної сторінки.
- Root layout завантажує 5 шрифтових сімей; Poppins не використовується ніде,
  Nunito — лише успадкований базовий шрифт старих сторінок (`/profile`, `/shopping-list`).
- Кроки квізу рендеряться динамічно (SSR на кожен запит), переходи між кроками не
  мають prefetch — кожен `router.push` чекає RSC-запит.
- Ефект у `StepRenderer` предекодує всі ~21 AVIF (~1.5 МБ) одразу на маунті першого
  кроку, конкуруючи зі шрифтами/JS/LCP.
- Картинки квізу — повнорозмірні (`breakfast.avif` 180 КБ, `kollaz.avif` 140 КБ) для
  колонки ≤480 px.
- Усі 7 слайдів `ExampleWorkSection` мають `priority` → 7 eager preload з
  fetchpriority=high на лендінгу та сторінці оплати.
- `/payment/plan` дізнається про знижку лише після клієнтського `fetch('/api/discount')`.
- `next/image` без `formats` перекодовує AVIF у (частіше більший) WebP.

## Рішення

### 1. Аналітика: лінивий PostHog

- `src/lib/analytics/index.ts`: статичний імпорт `posthog-js` → динамічний
  `import('posthog-js')` усередині `ensurePosthog()` (одноразовий).
- Події, викликані до завантаження модуля, накопичуються в черзі в пам'яті **зі своїм
  timestamp** і флашаться після ініціалізації (порядок і час не спотворюються).
- `beacon: true` до завантаження модуля — подія йде в чергу (прийнятний trade-off:
  на сторінці оплати PostHog встигає завантажитись задовго до кліку оплати).
- `AnalyticsProvider` НЕ змінюється: PageviewTracker стріляє $pageview на маунті,
  що однаково запускає завантаження чанка; виграш дає сам динамічний import()
  (поза First Load JS), а idle-затримка лише відклала б флаш черги подій.
- Публічний API фасаду (`track`, `identify`, `capturePageview`, `resetIdentity`)
  не змінюється. Vitest-тести фасаду адаптуються під асинхронну ініціалізацію.

### 2. Шрифти

- Видалити Poppins повністю: імпорт у `src/app/layout.tsx`, утиліту `.font-poppins`
  і `--font-poppins` у `globals.css` (використань нуль).
- Nunito прибрати з root layout (включно з `nunito.className` на body); винести в
  спільний модуль `src/lib/fonts/legacy.ts`, який підключають лише
  `profile/layout.tsx` і `shopping-list/layout.tsx` (клас на кореневому елементі
  цих сторінок). Візуально старі сторінки не змінюються.

### 3. next/image

- `next.config.ts`: `images: { formats: ['image/avif', 'image/webp'], minimumCacheTTL: 2678400 }`.

### 4. Квіз

- **Статичні кроки:** серверний `src/app/onboarding/[step]/layout.tsx` з
  `generateStaticParams()` по ключах `STEPS`. `dynamicParams` залишити `true`
  (невідомий ключ обробляється клієнтським редіректом на перший незаповнений крок —
  з `false` це стало б 404).
- **Prefetch:** у `StepRenderer` ефект викликає `router.prefetch()` для наступного
  і попереднього кроків (з поточних answers).
- **Предекод у дві хвилі:** одразу — картинки поточного + 2 наступних кроків;
  решта — у `requestIdleCallback` (fallback `setTimeout(2500)`).
- **Стиснення асетів:** одноразовий скрипт (sharp) ресайзить `public/onboarding/*.avif`
  понад ~60 КБ до ширини ≤ 960 px, quality ~50, з перезаписом. Візуальний контроль
  кожного зміненого файлу. Очікування: ~1.5 МБ → ~0.6–0.7 МБ.

### 5. Сторінка оплати /payment/plan

- `page.tsx` стає серверним компонентом: читає httpOnly-куку знижки (логіка
  `/api/discount` виноситься у спільний хелпер) і передає `initialDiscount` у
  клієнтський `PlanPageClient`. Клієнтський `fetch('/api/discount')` видаляється;
  API-роут лишається для інших споживачів.
- Роут стає динамічним (кука) — прийнятно: без походів у БД, таймер і ціни в
  першому HTML.
- `FaqSection` → серверний компонент (нуль гідраційного JS); футер/трикутник — у
  серверній частині. `BenefitsSection`, `ResultsSection`, слайдер, картки планів —
  клієнтські (залежать від localStorage/стану).
- `fetch('/api/subscription/me')` лишається клієнтським.

### 6. Слайдер ExampleWorkSection

- `priority` тільки для слайда `index === 0`; решта — `loading="eager"` без
  priority (`lazy` не спрацює для зсунутих translateX слайдів поза viewport).

### 7. Кешування статичних AVIF

- `headers()` у `next.config.ts`: `Cache-Control: public, max-age=31536000, immutable`
  для `/onboarding/:path*` (AVIF) та `/example-*.avif`.
- Домовленість: при заміні картинки — нове ім'я файлу.

## Верифікація

1. `npx tsc --noEmit` + `npm test`.
2. `next build` (dev-сервер зупинений!): порівняти First Load JS до/після
   (заміряти «до» перед початком); кроки квізу — static (`●`).
3. `next start` + ручний прохід: квіз від першого кроку до оплати, слайдер, таймер
   знижки з кукою і без, події аналітики (console.debug у dev).
4. Розміри `public/onboarding` до/після.

## Ризики

- Черга аналітики: втрата подій при миттєвому закритті вкладки до ініціалізації —
  еквівалентно наявній батч-черзі PostHog.
- Динамічний рендер `/payment/plan`: мінімальний TTFB-кост (без БД) в обмін на
  таймер/ціни в першому HTML.
